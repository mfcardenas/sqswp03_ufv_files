# Lab 2: Requirements Elicitation Techniques - Prompt

## Learning Objectives
By the end of this laboratory, students will be able to:

1. **Apply multiple elicitation techniques** including interviews, questionnaires, observation, and document analysis
2. **Design effective elicitation instruments** for different stakeholder types and contexts
3. **Analyze and synthesize requirements** from multiple sources using systematic methods
4. **Identify and resolve conflicts** between requirements from different elicitation techniques
5. **Evaluate elicitation technique effectiveness** and select appropriate methods for different scenarios
6. **Create comprehensive elicitation plans** that combine multiple techniques effectively

## Scenario: E-Commerce Platform Requirements

You are a requirements engineer working for an e-commerce company that wants to develop a new customer loyalty program. The system needs to integrate with their existing e-commerce platform and provide personalized rewards, gamification elements, and analytics for business intelligence.

Your task is to elicit requirements from multiple stakeholders using various techniques and synthesize them into a coherent requirements specification.

## Tasks

### Task 1: Interview Planning and Execution (30 points)
Design and execute structured interviews with the following stakeholders:
- **Product Manager**: Focus on business objectives and strategic requirements
- **Marketing Manager**: Focus on customer engagement and promotional requirements
- **IT Manager**: Focus on technical constraints and integration requirements
- **Customer Service Representative**: Focus on operational requirements and user pain points

**Deliverables:**
- Interview guides for each stakeholder type
- Interview transcripts or summaries
- Analysis of key requirements identified
- Stakeholder priority matrix

### Task 2: Questionnaire Design and Analysis (25 points)
Create and analyze questionnaires for:
- **Current customers** (n=50): Usage patterns, preferences, pain points
- **Potential customers** (n=30): Expectations, feature priorities
- **Business partners** (n=10): Integration requirements, data sharing needs

**Deliverables:**
- Questionnaire templates with different question types
- Response analysis with statistical summaries
- Key insights and patterns identified
- Recommendations based on quantitative data

### Task 3: Observation and Contextual Inquiry (20 points)
Conduct observation sessions for:
- **Customer purchase process** observation
- **Customer service interactions** analysis
- **Employee workflow** in loyalty program management
- **Mobile app usage** patterns

**Deliverables:**
- Observation protocols and checklists
- Activity logs and workflow diagrams
- Bottleneck identification and recommendations
- Contextual inquiry findings

### Task 4: Document Analysis (15 points)
Analyze existing documentation:
- **Business requirements documents**
- **Technical specifications**
- **User manuals and help documentation**
- **Competitor analysis reports**
- **Regulatory compliance documents**

**Deliverables:**
- Requirements extraction matrix
- Gap analysis report
- Document cross-reference analysis
- Missing requirements identification

### Task 5: Technique Integration and Synthesis (10 points)
Combine findings from all techniques:
- **Requirements consolidation** from multiple sources
- **Conflict identification and resolution**
- **Requirements prioritization** matrix
- **Traceability establishment** between techniques

**Deliverables:**
- Consolidated requirements specification
- Conflict resolution log
- Requirements traceability matrix
- Final recommendations report

## Assessment Criteria

### Technical Implementation (40%)
- **Code Quality**: Well-structured, documented, and efficient code
- **Functionality**: All features work as specified
- **Error Handling**: Proper validation and error management
- **User Interface**: Intuitive and professional design

### Requirements Engineering Practices (35%)
- **Technique Selection**: Appropriate methods for different contexts
- **Stakeholder Analysis**: Comprehensive coverage of stakeholder types
- **Requirements Quality**: Clear, complete, consistent, and testable requirements
- **Documentation**: Professional and well-organized deliverables

### Analysis and Synthesis (25%)
- **Data Analysis**: Effective use of statistical and qualitative analysis
- **Synthesis Quality**: Logical integration of multiple data sources
- **Conflict Resolution**: Systematic approach to resolving contradictions
- **Recommendations**: Actionable insights based on findings
